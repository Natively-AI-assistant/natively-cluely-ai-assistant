--- Raw model answer ---
**Positional encoding** in this paper uses fixed sine and cosine functions of different frequencies, added to the input embeddings. For position `pos` and dimension `i`:

$$PE_{(pos, 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
$$PE_{(pos, 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

The wavelengths form a geometric progression from $2\pi$ up to $10000 \cdot 2\pi$.

The reason behind choosing sine and cosine is that it lets the model easily learn to attend by **relative positions**. Because of the trig identity $\sin(a+b) = \sin(a)\cos(b) + \cos(a)\sin(b)$, for any fixed offset $k$, $PE_{pos+k}$ can be written as a linear function of $PE_{pos}$. So the model doesn't have to memorize absolute positions, it can pick up on "how far apart" two tokens are using simple linear combinations. They also tried learned positional embeddings and got nearly identical results, so sine/cosine was kept as the default since it works without extra parameters and generalizes to longer sequences than those seen in training.
